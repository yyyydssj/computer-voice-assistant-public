## 目标

将实时音频流转写成可供对话主控判断的中文文本与识别元数据，同时确保不确定、空白、重叠或重复的识别结果不能驱动 Agent、电脑工具或安全授权。

ASR 是实时对话中的输入理解组件，不是单轮录音工具。一次发言识别结束后，系统仍保持当前连续对话会话，等待用户继续说话。

## 默认 Provider

- 默认：`sherpa-onnx + SenseVoice`。
- 可选：VoiceStudio 流式 ASR Provider，但必须遵守本文相同的事件、去重和安全规则。
- Provider 只提供识别结果和相关元数据，不拥有 Agent 决策、工具调用、授权或 VoiceProfile 修改权限。

## 统一结果模型

`transcribe(audio)` 或流式等价接口至少返回：

- 规范化后的识别文本；
- 是否为空识别；
- 稳定性/置信度信息（如果 Provider 可提供）；
- 是否检测到非人声事件；
- 是否存在多人重叠或无法可靠分离的语音；
- 当前发言与识别事件标识，用于防止重复提交；
- 最终结果标记，区分 interim 与 final。

具体数值阈值不在规划阶段写死，须在阶段 13 的真机测试中按设备、环境噪声和模型输出校准；但“不确定语音不能驱动电脑操作或授权”是硬规则。

## 已确认的实时对话处理规则

### 1. 清晰且稳定的最终识别

- 只将稳定的 final 结果提交一次。
- 提交给对话主控，由 Agent 在同一实时会话中判断这是闲聊还是电脑任务。
- interim 结果只可用于界面实时预览，不进入正式对话历史，不生成计划，不调用工具，也不产生授权。

### 2. 没听清、低置信度或空识别

当系统无法可靠理解当前发言时：

1. 不显示错误识别文本；
2. 不写入正式对话历史；
3. 不发送给 Agent；
4. 不生成或修改执行计划；
5. 不调用任何电脑工具；
6. 不产生 L2/L3 授权；
7. 使用当前已确认的 VoiceProfile 语音提示：`没听清，请再说一遍。`；
8. 保持当前实时对话会话，并自动继续监听下一句话。

用户不需要重新按键、重新唤醒或重新进入会话。该提示是对话修复动作，不算一轮有效用户输入。

### 3. 多人重叠说话

- 如果检测到多人同时说话或主要说话人无法可靠确定，不使用本次识别结果。
- 不显示可能错误的转写，不提交 Agent，不生成计划，不调用工具，不产生授权。
- 使用当前 VoiceProfile 提示：`请一次只说一个人。`
- 提示后保持当前实时对话并继续监听。
- 多人重叠语音不得用于电脑操作、L2 授权或 L3 第二重确认。

本阶段不要求做复杂的说话人分离；无法可靠处理时应拒绝本次输入，而不是猜测。

### 4. 重复识别事件

- 每次用户发言生成唯一 `utterance_id`；每个 Provider 事件保留 `event_id` 或单调序号。
- 同一 `utterance_id` 只允许一个 final 结果进入对话主控。
- 重复 final、迟到 interim、重连后重放事件和文本相同但事件身份重复的结果必须静默丢弃。
- 去重不能只依赖文本相同，因为用户可能连续说两次同一句话；必须结合发言边界和事件身份。
- 已被判定为没听清、多人重叠、取消或设备异常的 `utterance_id` 必须关闭，之后到达的结果不能重新激活该轮输入。

### 5. L3 固定短语识别

L3 第二重确认只接受清晰、独立、完整匹配的：

```text
确认执行
```

不接受：

```text
确认
可以
执行吧
我确认执行
确认执行一下
```

还必须同时满足：

- 当前处于有效的 L3 独立确认状态；
- 授权提示已完整播放；
- 识别结果不是 interim、低置信度、多人重叠或重复事件；
- 结果与当前 `plan_id`、版本、哈希、动作和有效期绑定；
- 提示被打断、设备异常、计划变化、超时或用户取消后，本次确认状态立即失效。

## 启动阶段模型加载失败与超时（已定稿）

- ASR 模型加载是可降级能力，不是程序启动的全局阻塞条件。程序先启动正式界面、文字输入、DeepSeekHarness 接入适配器、本地安全链和审计基础设施；ASR 在独立启动任务中加载。
- ASR 在独立的、有上限的启动期限内未完成，或加载失败、模型文件不完整、Provider 初始化失败时，立即标记为 `unavailable_startup`，清理未完成的加载任务和临时资源，并自动进入文字输入模式。
- 文字输入模式在 ASR 启动失败时立即可用；用户仍可闲聊或提交电脑任务，电脑任务继续经过 Schema、PathGuard、PolicyEngine、L2/L3 授权、本地受控执行器和 ResultVerifier。
- 启动超时不能通过无限等待、后台循环重启或连续弹窗来掩盖；只记录一次脱敏故障状态，并把后续健康检查与重新启用留给独立的恢复状态机。
- 如果 ASR 在启动降级后又恢复，不得突然抢占用户正在使用的文字输入，也不得自动把当前输入模式切回语音；只显示“语音识别已恢复，可以切回语音输入”，切回仍遵守用户明确请求、安全空闲点和本机联合测试规则。
- ASR 启动失败不创建、不恢复、不续跑任何电脑任务；程序启动时不存在可执行的旧授权，若发现上次遗留任务仍按崩溃/重启恢复规则处理。
- 具体启动期限、模型加载并发度和真机资源阈值留到阶段 13 校准，但无论阈值如何配置，都必须有明确上限，不能无限阻塞文字模式。
## 会话预热与运行期故障（已定稿）

### ASR 会话预热

- 用户请求语音输入后，ASR 在独立、可取消且有明确上限的会话任务中预热；界面显示“正在准备语音输入”，并始终保留文字输入、取消和重新检测入口。
- 预热期间采集的声音只用于本次设备/链路准备，不进入正式识别，不积累到加载完成后补识别，也不得提交 Agent、停止控制或授权状态机。
- 预热成功后必须清除预热音频与旧 Provider 事件，并创建全新的 `session_id` 与 `utterance_id`，然后才允许正式收音。
- 预热失败、超时或取消后，清理本轮状态并进入文字输入模式；不得创建 Agent 请求、执行计划或授权。
- 用户手动重试是新的、有上限的尝试，不是延长旧等待；不得复用旧音频、旧事件、旧请求或旧授权。

### 运行期 ASR 故障

- 运行期故障只结束当前语音输入轮次。录音或识别中故障时，丢弃当前 `utterance_id`、interim、临时音频和旧事件，不提交 Agent。
- 最终文本与故障事件的先后顺序无法可靠确认时，默认不提交。只有最终事件明确属于当前 utterance、顺序可靠、尚未重复且尚未创建 `request_id` 时，才可接纳并提交一次。
- 一旦已经创建 `request_id`，随后发生的 ASR 故障不得撤回、重发或创建第二个请求；请求继续按 Agent/API 与任务状态规则处理。
- 半句“停”“取消”“允许”“确认执行”以及任何不完整、interim 或迟到语音均不生效。L3 语音确认期间发生 ASR 故障时，当前确认轮次立即失效。
- ASR 故障本身不得暂停、取消、回滚、重试或重启正在进行的电脑任务；系统只关闭当前语音轮次并自动进入文字输入模式。

建议工程状态：

```text
ASR_UNAVAILABLE_STARTUP
ASR_READY
ASR_SESSION_WARMING
ASR_SESSION_ACTIVE
ASR_SESSION_FAILED_RUNTIME
ASR_COOLDOWN
ASR_PROBING
ASR_RECOVERED_PENDING_USER
```

## ASR 整体不可用时的文字模式降级

当 ASR 初始化失败、模型无法加载、Provider 退出，或运行期故障导致系统无法继续可靠识别语音时，自动进入**文字输入模式**。这只改变输入通道，不更换 AI，也不降低电脑操作的安全等级。

降级流程：

1. 停止语音识别，并关闭、清除当前尚未完成的识别轮次；
2. 当前轮残留音频不得继续提交，也不得发送给未经用户配置的其他 ASR Provider；
3. 不自动切换 Windows 语音识别、云端 ASR 或其他识别服务；
4. 界面明确显示“语音识别不可用”、脱敏后的故障原因和当前文字输入状态；
5. 用户可以继续用键盘输入闲聊或电脑任务；
6. TTS 可用时采用“文字输入、语音输出”，TTS 也不可用时采用纯文字交互。

文字输入仍进入原有 Agent 链路：

```text
用户键盘输入
→ 创建新的 request_id
→ DeepSeekHarness Python SDK
→ 同一个 Harness Agent
→ 闲聊回复，或提出结构化电脑任务计划
```

Harness Agent 仍只负责理解、规划和汇报，不能因为 ASR 不可用而直接自由操作电脑。电脑任务必须继续经过：

```text
DeepSeekHarness Agent
→ Schema 校验
→ PathGuard
→ PolicyEngine
→ 用户 L2/L3 授权
→ 本地受控执行器
→ ResultVerifier
```

文字模式下的授权规则：

- L0/L1 继续遵循原有只读限制；
- L2 仍须在正式弹窗中点击“允许执行”；
- L3 必须先点击“允许执行”，再在独立确认输入框完整键入 `确认执行`；
- L3 确认仍绑定当前 `plan_id`、版本、哈希、动作和有效期；
- ASR 故障不得降低权限等级，不得复用旧确认或旧授权。

### ASR 恢复探测与切回语音输入

文字模式允许在后台进行低频 ASR 健康检查，但健康检查只负责发现恢复，不得自动改变当前输入模式。

恢复探测规则：

- 优先检查本地模型、Provider 进程、设备可用性和固定本地测试音频；不得拿用户正在说的话作为后台测试材料；
- 健康检查不得把测试音频上传到云端或未经用户配置的 Provider；
- 必须连续多次通过检查后才标记为“ASR 已恢复”，具体次数和间隔在真机测试阶段配置，不在规划阶段写死；
- 检查失败时继续保持文字模式，不反复弹窗或循环播报；
- 用户可在设置或状态栏中手动触发“重新检测语音识别”。

恢复后只提示：`语音识别已恢复，可以切回语音输入。` 系统不得自动切回。只有用户点击“切回语音”或通过当前文字输入明确要求切回后，才能进入切换流程。

切换只能发生在安全空闲点，不得发生在以下状态：

- 用户正在键入尚未提交的文字；
- Agent 正在生成回复或 TTS 正在播报当前回复；
- 用户正在查看或修改执行方案；
- 正在等待或处理 L2/L3 授权；
- 电脑任务正在执行、停止、取消、中止或恢复扫描。

如果用户已要求切回但当前不在安全空闲点，界面显示“将在当前流程结束后切回”，待进入安全空闲点后再执行；不得中断当前流程或提前启用麦克风输入。

实际切回前必须：

1. 清除故障前遗留的音频、缓冲区、Provider 事件和未完成 `utterance_id`；
2. 创建新的语音输入会话边界，不复用旧 `utterance_id`、`event_id`、`request_id`、确认状态或授权；
3. 在用户已请求切回的前提下，执行一次仅限本机的麦克风与 ASR 联合测试；测试音频不提交 Agent、不写入正式对话历史，并按临时音频规则删除；
4. 联合测试通过后才启用正常语音输入；失败则继续保持文字模式，显示脱敏原因，并允许稍后重新检测。

## GitHub 对比优化后的工程补充

- 工程上必须分离音频 callback、`AudioBus` 帧、VAD 片段和 ASR 解码块的粒度。callback 不得直接调用 Agent，也不得把一次设备回调误当作一个 utterance 或一个最终识别事件。
- 每个 ASR Provider 必须声明能力矩阵：`supports_interim`、`supports_final`、`supports_vad`、`supports_overlap_detection`、`supports_speaker_identity`、`supports_confidence`、`supports_language_detection`。
- `unsupported` 与 `not_detected` 必须分开：Provider 不支持多人重叠、说话人身份或置信度时，系统不能把缺失字段解释为“未检测到”“单人说话”或“置信度正常”。
- 不得默认假设 SenseVoice 或 sherpa-onnx 能可靠提供多人重叠检测、说话人身份或跨环境可比较的置信度；相关安全判断只有在能力声明、真机测试和阈值证据均满足时才能启用。
- 音频和识别事件至少携带 `audio_session_id`、`provider_generation`、`provider_stream_id`、`utterance_id`、`event_sequence`、`event_kind`、Provider timestamp、`received_at` 和 `terminal_reason`。
- generation 或 stream 变化后，旧流的迟到、重复、乱序和最终事件不得提交 Agent；终态后同一 utterance 的后续结果只能记录诊断。
- 当 Provider 不支持可靠的最终文本、重叠检测、身份或必要的控制短语判定时，不默认开放语音 L3；应继续使用正式界面的独立确认输入或更严格的本地确认路径。
- 统一对比证据见 [GitHub 固定版本源码对比与方案优化](./research/github-comparison-and-optimization.md)。

## 验收

- 启动时 ASR 模型失败或超时不会阻塞界面；用户可立即使用文字输入，并能继续自然闲聊或进入电脑任务规划。
- 清晰中文发言只提交一次，并能继续自然闲聊或进入电脑任务规划。
- 没听清时只语音提示“没听清，请再说一遍”，不显示错误文本，随后继续监听。
- 空识别、多人重叠、低可靠性、迟到和重复事件均不能驱动 Agent、工具或授权。
- 连续说两次相同内容时，只要属于两个不同 `utterance_id`，两次都可被正常处理。
- L3 只接受当前有效确认状态中的完整固定短语“确认执行”。
- ASR 整体不可用时自动进入文字输入模式，不自动切换到未经配置的识别服务，也不提交残留音频。
- 文字输入继续使用同一个 Harness Agent；电脑任务仍完整经过 Schema、路径、策略、授权、本地执行和结果验证。
- 文字模式下 L2/L3 不降级；L3 可在独立确认输入框完整键入“确认执行”，旧授权不得复用。
- 后台健康检查可以发现 ASR 恢复，但不会监听用户话语做测试、上传测试音频或自动切回语音输入。
- 只有用户明确请求且系统处于安全空闲点时才切回；切回不打断键入、回复、方案、授权、执行或恢复流程。
- 切回前清除旧输入状态并完成本地联合测试；测试失败时继续保持文字模式。
- 会话预热期间的音频不进入正式识别或 Agent；预热失败、超时或取消均不会创建请求、计划或授权。
- 运行期故障只结束当前语音输入轮次；不完整语音、顺序不确定的最终文本和半句控制/确认短语均不能生效。
- 已创建 `request_id` 后发生 ASR 故障时不撤回、不重发、不创建第二个请求；音频故障也不改变正在执行的电脑任务。


## ASR accepted final and intent routing (2026-09-24)

The only ASR business submission point is the ResultGate-accepted final:

```text
ASR accepted final
-> ConversationManager(source=asr)
-> IntentRouter
-> RouteHandoff
-> Agent / ActionPlan / Safety
```

- Interim, unaccepted final, empty, duplicate, late, out-of-order, and old-generation events do not create a handoff.
- ASR failure may trigger existing text fallback or a session prompt, but cannot bypass IntentRouter and submit directly to Agent.
- An ASR final means the text was accepted; it does not mean intent confirmation or authorization. Slots remain candidates and side effects use the full safety chain.
- The ASR entry must carry `request_id`, `conversation_id`, `turn_id`, `source=asr`, `raw_text`, and `created_at`.
