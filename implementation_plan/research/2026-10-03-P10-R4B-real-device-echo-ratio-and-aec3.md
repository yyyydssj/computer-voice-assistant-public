# P10 R4-B-3 / R4-B-4：真机"回声/用户语音比"与真机 AEC3 双讲实测

- 建立时间：2026-10-03
- 工具：`tools/p10_r4b3_echo_ratio_probe.py`（量比值）、`tools/p10_r4b4_realtime_doubletalk_probe.py`
  （真机 AEC3 双讲 + `--echo-only --delay-sweep` 复核）
- 需要 `--live-opt-in` 才开设备；**默认不落盘任何音频**；无 DeepSeek、**零计费**
- 上游：`research/2026-10-03-P10-R4B-2-doubletalk-findings.md`（合成路径 go/no-go）、
  `checkpoints/2026-10-03-P10-R4B-2-planC-cooldown-handoff.md`（方案 C 冷却窗口）

---

## 1. 结论（一句话）

**AEC3 在本机真的有效（真机 ERLE 10.3 dB，最佳延迟提示下 15.5 dB），但单靠它压不干净**：
最佳情况下仍有 **80/289 ≈ 28%** 的 20 ms 帧残余回声超过打断能量门 600（未处理时 59%）。
⇒ 本机要安全打断需要**三件套**：AEC3 + 冷却窗口（已落地）+ **残余回声地板感知的动态门槛**（未做）。
阶段 0 的"条件性 no-go"应修正为：**AEC3 不是不可用，而是不够用**。

## 2. R4-B-3：回声 / 用户语音比（真机）

命令：`.\.venv\Scripts\python.exe tools\p10_r4b3_echo_ratio_probe.py --live-opt-in`
素材：本机真实 TTS 音频 `implementation_plan/checkpoints/artifacts/2026-09-28-P7-local-voicestudio/eff172cb.wav`
（24 kHz 单声道 16-bit、2.0 s，与生产播放路径同格式），用**生产同款 waveOut 后端**播放 ×2。

| 量 | 数值 |
|---|---|
| 麦克风 | 麦克风阵列 (Realtek(R) Audio) @ 48 kHz |
| 噪声底（1.5 s） | p50 **72** / max 2824（历史 p50≈47.7 / max≈150） |
| 回声段（3.73 s） | p50 **846** / p95 2413 |
| 用户语音段（8 s，296/400 帧高于噪声） | p50 **1917** / p95 8360 |
| **ERL（播放→麦克风回损）** | **13.7 dB** |
| **回声 / 用户语音比** | **−7.1 dB**（用户语音比回声高 7.1 dB） |
| 用户语音 vs 能量门 600 | **+10.1 dB** |
| 回声 vs 能量门 600 | **+3.0 dB**（不处理时自己的声音就会越门 ⇒ R4 三轮自触发的根因） |

**⚠️ 不可复现的部分（如实记录）**：同一天的 R4-B-4 A 段（同一用户、同一坐姿口径）用户语音
p50 只有 **1037**（与本次 1917 差 **5.3 dB**），而回声侧两次为 846 / 1020。
⇒ 该比值**随用户说话音量/位置在 ≈0 ~ −7 dB 之间浮动**，**不能**当成稳定的"好档"。
单次量测不足以定档；这也是为什么必须看第 3 节的绝对 ERLE/门槛余量。

## 3. R4-B-4：真机 AEC3 双讲 + 延迟扫描

### 3.1 三段录制 + 双讲结果（首次运行，含用户说话）

| 量 | 数值 |
|---|---|
| 实测回声延迟（B 段互相关） | **409 ms** |
| B 段回声 → AEC3 残差（p50） | 1020 → **519** ⇒ 真机 **ERLE 5.87 dB** |
| 残差 vs 能量门 | **−1.26 dB**（p50 勉强门下），但 **137/289 帧超门**（未处理 209） |
| A 段用户语音 p50 | 1037（有效帧 140） |
| C 段双讲 | 麦克风 p50 3178 → AEC3 残差 p50 1728 |
| 双讲后用户语音估计 | **1648**（vs 门 **+8.8 dB**） |
| 工具判定 | no_go（回声抑制不足） |

### 3.2 复核：只放音 + `stream_delay_ms` 扫描（无需用户配合）

B 段 289 帧；回声麦克风 p50 = **790**；未处理时 **171** 帧超门。

| `stream_delay_ms` | 真机 ERLE | 残差 p50 | 残差超门帧 |
|---|---|---|---|
| 0 | 7.74 dB | 324 | 104 |
| 100 | 12.15 dB | 195 | 73 |
| 200 | 10.27 dB | 242 | 87 |
| 250 | 13.52 dB | 167 | 70 |
| **350（最佳）** | **15.54 dB** | **132** | **80** |
| 392（本次实测延迟） | 10.32 dB | 241 | 95 |
| 450 | 6.98 dB | 354 | 117 |
| 500 | 8.00 dB | 314 | 107 |

### 3.3 从真机数据得到的四条事实

1. **真机 ERLE 10.3 dB（实测延迟）/ 15.5 dB（最佳延迟）**；合成回声路径为 23–38 dB
   ⇒ **内置麦克风阵列 DSP 让可消的线性分量损失约 8–15 dB**（R2b-2 只测到"不可相关"，本次给出量化）。
2. **延迟提示敏感**：0–500 ms 内 ERLE 在 **7–15.5 dB** 间波动 ⇒ 接线必须实测延迟并留裕量，不能写死。
3. **残余回声仍会越门**：最佳情况残差 p50 比门低 7.9 dB，但 **28% 的帧仍超门**（TTS 起音尖峰）
   ⇒ 只靠 AEC3 + 固定门槛仍会自触发。
4. **问题不在用户语音侧**：双讲后用户语音估计 1648（比门高 8.8 dB）
   ⇒ AEC3 没有把用户语音压到不可用（与阶段 0 合成路径的结论不同——那里回声 ≥ 用户时才会压很狠）。

---

## 4. 决策

- **修正阶段 0 的结论**：不是"AEC3 在本机大概率不可用"，而是**"AEC3 有效但不足以单独解决自触发"**。
- **不接线**（本批只产出证据）：接线的前提是先有**残余回声地板感知的动态门槛**，否则 ~28% 帧仍会误停播。
- **下一步（三件套）**：
  1. AEC3 接进会话（`--aec-engine webrtc`，默认关）；
  2. 已落地的冷却窗口（`--barge-in-cooldown-ms`，建议 1000）；
  3. **新增**：播放期能量门 = `max(speech_threshold, 残余回声地板 × 裕量)`，地板由 AEC3 残差的滑动分位数实时估计；
     并如实暴露 `residual_echo_floor_pcm16` / `gate_in_playback` 等事实。
- 三件套做完再真机试听（需用户在场），届时还要复测延迟（建议在启动时做一次 ~1 s 的延迟探测）。

## 5. 未做 / 局限（**不得伪造**）

1. **样本量很小**：R4-B-3 一次、R4-B-4 两次（其中一次兼作延迟扫描）；没有做重复性统计。
2. **用户语音电平不可复现**（两次差 5.3 dB）⇒ 比值"−7.1 dB"只是那一次的观测值。
3. **最佳延迟是样本内拟合值**（同一段录音上扫出来的最好点），不是独立复核过的稳健最优。
4. **系统音量没有记录**（未接音量 API）；所有数值只在当时的系统音量下成立。
5. **播放素材是离线 TTS wav**，不是 VoiceStudio 实时输出（电平可能有差异）。
6. 延迟探测用的是**互相关**（我自己的实现），与 AEC3 内部延迟估计不是同一口径；
   两者的差值（实测 392 ms vs 扫描最佳 350 ms）约 40 ms。
7. **未做**：残余地板感知门槛、AEC3 会话接线、三件套真机试听；耳机/外接麦克风场景未测。
8. 工具**未加单元测试**（`tools/` 下开发测量工具，不在生产路径）；本批**未改任何生产代码**。

## 6. 真机运行中暴露并修掉的一个缺陷（如实记录）

`p10_r4b3_echo_ratio_probe.py` 首次真机运行时，在打印含 `≫`（U+226B）的档位标签处抛
`UnicodeEncodeError`（GBK/936 控制台）——与 P10 R4-A 记录的真机缺陷同类。
修复：新增 `safe_write()`（编码不可表示时按 `replace` 重试），并用合成报告在 GBK 流上离线验证。
后果：**那一次运行没有写出 JSON artifact**（崩在写文件之前），R4-B-3 的数值来自控制台输出（命令可复现）。
