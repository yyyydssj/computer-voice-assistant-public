# 发现与决策

## 需求
- **控制电脑范围**：类似 Claude Code / Codex 的 agent；第一阶段只做「命令与文件操作」，后续逐步补充 GUI 自动化、浏览器自动化等
- **分阶段递进**：先做简单核心，不一开始求全
- **交互形态（最终目标）**：全语音闭环——麦克风语音输入 → 转文字 → 大模型 → 语音输出（TTS）
- **大模型来源**：云端 API（不是本地模型）
- **运行形态**：做成一个程序，开启后常驻后台，用关键词唤醒（类似智能音箱）
- **安全边界**：读操作（查文件/列目录/查状态）直接执行；写/删/改/执行命令前语音确认
- **节奏**：先讨论确定方案，实现时机由用户决定
- **唤醒词**：小饼（与微信机器人一致）
- **对话模式**：唤醒后连续对话多轮，静默超时（约 30 秒）自动回待机
- **播报长度**：靠人设约束（简短），工具执行结果由 AI 总结成简短播报，不硬性截断
- **命令执行**：用 PowerShell；默认工作目录为新建专用工作区 `<STUDY_ROOT>\AI工作区`
- **文件编码**：自动检测（UTF-8 优先，失败回退 GBK）
- **大文件限制**：宽松限制（约 10MB 上限），二进制文件拒绝读取
- **确认措辞**：确认词「确认/可以/好/行/执行/嗯/对」，取消词「取消/不/别/算了」，紧急停止「停/停止」
- **路径保护**：黑名单保护系统目录（C:\Windows、C:\Program Files、C:\Program Files (x86)、AppData）禁止写/删，其余允许但写/删走确认
- **会话历史**：保留最近 20 轮，静默回待机后历史保留（下次唤醒还记得），重启后清空
- **跨会话记忆**：只保留「重点」（AI 提炼的用户偏好/重要事实）+ 用户明确说「记住」的内容，存 memory.md，重启后恢复；全量对话历史不持久化
- **启动方式**：第一版手动启动，自启动/守护作为后续迭代
- **日志内容**：记录对话文字 + 执行操作 + 错误；不记 API key、不存音频
- **音色识别**：唤醒绑定声纹，只认主人声音（别人喊「小饼」不响应）

- **日志**：记录每次对话与执行的操作，存 logs/，便于查错

## 研究发现
### 对标项目（GitHub 调研 2026-09）
| 项目 | star | 定位 |
|------|------|------|
| openinterpreter/open-interpreter + 01 | 高 | 自然语言控制电脑（执行代码/命令），01 是语音版，最直接对标 |
| huggingface/speech-to-speech | 13k | 用开源模型构建全语音 agent，纯本地语音闭环 |
| huangjunsen0406/py-xiaozhi | 3.4k | AI 助手生态，MCP 集成、多模态、跨平台语音 |
| feder-cr/AIHawk | 30k | 浏览器/computer-use agent |
| trycua/cua | 22k | computer-use 2.0 框架，跨 OS、沙箱 |
| simular-ai/Agent-S | 12k | 像人一样用电脑，规划/记忆/视觉 |
| HeyWillow/willow、rhasspy、jarvis | 2~3k | 本地离线语音助手，唤醒词+意图+家居控制 |

### 对比后发现需完善的点
1. 会话状态机未明确（待机/录音/转写/思考/确认/执行/播报/打断 的状态转换）
2. 缺对话历史与上下文记忆（多轮对话需带历史）
3. 缺打断能力（AI 说话时用户插话打断，barge-in）
4. 缺紧急停止（执行危险操作时能喊停）
5. 工具层硬编码，可用 MCP 做成可插拔
6. GUI 自动化后续扩展应走视觉方案（截图 + 视觉大模型）
7. ASR 可优化为流式，降低首字延迟


## 技术决策
| 决策 | 理由 |
|------|------|
| 对话大模型用 DeepSeek API | 已有 key（cc-connect 在用），便宜、中文好、支持工具调用 |
| 语音识别（ASR）用本地 sherpa-onnx + SenseVoice | 中文识别强、多语种+事件检测更稳、模型走 GitHub 可加速（替代 faster-whisper） |
| 语音合成（TTS）暂用 Edge TTS 兜底 | 豆包台湾腔大模型音色仅企业可用（个人被拒），台湾腔改为音色克隆待定（GPT-SoVITS 本地 / 阿里 CosyVoice 云端），等用户准备台湾腔样本 |
| 声纹识别用 speechbrain（ECAPA-TDNN） | 镜像可装、成熟开源，可嵌入唤醒环节做主人验证（wespeaker 不在 PyPI，弃用） |
| system prompt 复用 cc-connect 小饼人设，独立存本项目的 ../persona.md | 语音助手专属人设文件，与微信 bot 分开维护，语音版精简适配 |
| 架构预留前后端分离（核心服务 + 可换前端） | 未来接手机（微信/App/网页）无需重写核心，方向暂不定 |
