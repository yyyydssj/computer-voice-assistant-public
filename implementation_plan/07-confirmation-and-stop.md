## 目标

危险操作先确认，并保证用户在实时对话、等待授权和任务执行期间都能明确喊停。“停”是高优先级控制指令，但不等于关闭实时语音助手。

## 已定稿：“停”的上下文语义

### 1. 仅在聊天或语音播报

当没有电脑任务正在执行、AI 只是在生成回复或播放 TTS 时：

- 立即停止当前回复生成和 TTS 播放；
- 清空这次回复尚未播放的语音队列；
- 不退出持续实时对话，不关闭程序；
- 立即回到监听状态，用户可以继续说话。

### 2. 正在等待 L2/L3 授权

- 立即停止授权提示语音；
- 取消当前确认状态并关闭确认窗口；
- 当前确认窗口、已产生的授权状态和只识别到一部分的确认短语全部作废；
- “停”本身不构成拒绝之外的任何新授权，也不能被当成 L3 固定短语的一部分。

计划可以继续作为只读记录供用户查看，但再次申请执行前必须重新检查计划与当前状态，并建立新的确认窗口；不得复用刚才的授权状态。

### 3. 正在执行电脑任务

```text
用户说“停”或点击停止
→ 立即停止 AI 播报
→ 阻止所有尚未开始的后续动作
→ 当前动作支持安全取消：发出协作式取消请求
→ 当前动作不可安全中断：等待该原子动作返回，但绝不开始下一步
→ 使原计划和全部授权失效
→ 使用受限只读工具重新扫描实际状态
→ 汇报已完成 / 未完成 / 状态不确定
```

附加硬规则：

- 不强杀正在执行的不可安全中断动作或底层进程；
- 已完成动作不自动回滚；
- 被阻止的后续动作不自动补做；
- 取消请求不等于动作一定没有产生副作用，仍须重新扫描；
- 如果当前动作迟迟不返回，只持续保持“停止后续动作”的状态并向用户展示当前情况，不得悄悄继续计划；
- 如需继续处理，必须重新规划、预检并完成新的 L2/L3 授权。

## 验收

- 聊天时说“停”只停止当前回复，随后仍能继续实时对话；
- 授权时说“停”会关闭确认状态，部分确认短语与旧授权不可复用；
- 执行时说“停”会阻止所有未开始动作；可安全取消的当前动作收到取消请求，不可安全中断的原子动作返回后不再开始下一项；
- 停止后不自动回滚、不自动补做，重新扫描并准确汇报实际状态；
- 继续任务必须重新规划、预检和授权。
## 已定稿：取消、中止与关闭程序

### 1. 取消：用户主动放弃当前任务

- 规划中或等待授权时取消：关闭当前任务，使计划、确认窗口和授权全部失效；如果尚未开始任何有副作用动作，不需要执行恢复扫描。
- 执行期间取消：先按“停”的规则阻止所有后续动作；当前动作可安全取消则请求取消，不可安全中断则等待原子动作返回；随后重新扫描实际状态。
- 已完成动作不自动回滚，未完成动作不自动补做。
- 取消后程序和持续实时对话保持运行，用户可以继续闲聊或提出新任务。
- 当前任务记录为 `user_cancelled`；如果已经执行了一部分，同时保存各动作的 `completed`、`not_completed`、`state_uncertain` 分类。

### 2. 中止：系统因风险、故障或前提变化被迫结束任务

以下情况至少必须触发系统中止：

```text
工具执行失败
执行前提变化
路径、文件哈希、参数或目标状态变化
审计无法满足执行要求
Schema、PathGuard 或 PolicyEngine 校验失败
动作结果或当前状态无法可靠确认
```

系统中止时：

- 立即阻止所有尚未开始的动作；
- 原计划、确认窗口及全部授权失效；
- 不自动重试、不跳过失败动作、不自动修复，也不自动回滚已完成动作；
- 使用受限只读工具重新扫描并汇报真实状态；
- 当前任务记录为 `system_aborted`；
- 是否创建新计划继续处理，只能由用户决定。

“取消”表示用户决定不再继续当前任务；“中止”表示系统判断当前任务不能安全继续。两者都不等于关闭语音助手。

### 3. 关闭程序：退出整个语音助手

#### 没有电脑任务执行

- 立即停止回复生成与 TTS；
- 停止麦克风监听和实时对话状态；
- 清理临时音频、未播放语音队列和进程内闲聊上下文；
- 按既定规则关闭 Provider、设备和后台组件后退出。

#### 正在规划或等待授权

- 将当前任务按用户取消处理；
- 关闭确认窗口，使计划执行资格和全部授权失效；
- 完成内存与临时音频清理后退出。

#### 正在执行电脑任务

```text
用户请求关闭程序
→ 进入“安全退出中”状态
→ 停止 AI 播报并阻止所有后续动作
→ 当前动作可安全取消：请求协作式取消
→ 当前动作不可安全中断：等待原子动作返回
→ 重新扫描并记录实际状态
→ 使原计划和授权失效
→ 完成清理
→ 退出程序
```

正常关闭不得强杀不可安全中断的动作。通过任务管理器、系统关机、断电或其他外部方式强制结束进程，统一按崩溃/重启恢复规则处理；下次启动不得自动续跑。

关闭过程的语音提示仍遵循人物模板，例如简短说明正在安全停止任务后退出；正式状态、动作结果和不确定项显示在界面或报告中。

## 已定稿：Agent/API 故障期间的执行控制

- 已冻结并完成授权的本地计划，不要求 Agent 在每个动作之间持续在线；执行器不得在执行途中向模型请求新的决定、参数或补充动作。
- 只有当本地停止信号、安全校验、冻结参数、审计写入和 `ResultVerifier` 均保持可用时，Agent/API 故障才不影响当前冻结动作链的既定语义。
- 如果故障影响停止控制、安全判断、动作参数、审计或结果验证，立即按系统中止处理：阻止后续动作，安全取消当前动作或等待原子动作返回，重新扫描实际状态，使计划与授权失效。
- 等待授权期间发生 Agent/API 故障，确认窗口关闭，当前计划执行资格及全部授权失效；未完成或未通过 Schema 的内容不得请求用户授权。
- 执行已经完成而自然语言汇报失败，不改变结构化执行结果；界面通过本地正式模板展示 `result.json` 对应事实，并单独提示汇报生成失败，不得再次执行。
- 限流、超时或服务端 `Retry-After` 不会触发自动重试；继续处理只能由用户明确决定，并按任务阶段建立新的请求、计划和授权。

### 追加验收

- 在授权窗口、动作间隙和结果汇报三个时点分别模拟 Agent 断线，均不会使用部分输出或旧授权继续越权执行；
- 本地控制能力完整时，冻结计划不需要模型逐步批准；任何需要模型临时决定的情况都会中止而不是猜测；
- 结果汇报失败时，结构化成功/失败事实保持不变，电脑动作执行次数不增加。
