## 1. 项目概览

## 项目最高原则：实时语音 AI 伙伴

本项目的本质不是“录音 → ASR → 播报”的单轮语音工具，而是：

> **用户与 AI 持续实时对话；既可以闲聊，也可以在提出需求时安全地操控电脑。**

产品层必须始终保持一个连续对话体验：

```text
用户说话
→ AI 实时理解
→ 判断是闲聊还是电脑任务
→ 闲聊：自然回应
→ 电脑任务：理解、规划、按安全规则请求授权、执行并汇报
→ 回到持续对话
```

“按键触发”“VAD 自动收音”“唤醒词”“连续对话”“实时打断”等是**开发阶段和底层实现顺序**，不是产品定位，也不是互相割裂的产品模式。任何阶段性降级都不得把项目重新定义成单轮录音应用。

## 并列最高原则：人物模板驱动的拟人表达

AI 面向用户说出的自然语言必须遵循用户选择并确认的人物模板。人物感不是后期装饰或可选功能，而是核心交互的一部分；由于闲聊是主要使用场景，设计和验收必须优先保证自然、口语化、有连续人格和情绪温度的对话体验，不能退化成客服腔、工具播报腔或机械状态提示。

- 闲聊、追问、澄清、没听清提示、错误说明、任务进度和执行结果的**语音表达**都要经过人物模板约束。
- `persona.md` 是当前人物模板的权威来源；只有用户可以修改、切换或停用人物模板，Agent 不得自行改写人设、关系、称呼或表达风格。
- VoiceProfile 决定“声音听起来怎样”，人物模板决定“AI 说什么、怎么说”；两者必须同时生效，但相互独立，不能用换音色代替人物表达。
- 人物表达不得削弱真实性、安全性和授权清晰度。路径、动作、风险、失败原因、确认范围以及固定授权短语必须准确完整；可以拟人化措辞，但不能撒娇诱导授权、淡化风险或省略关键信息。
- `plan.json`、审计日志、执行方案、结构化错误码等机器或正式文档不强制使用人物口吻；人物模板主要约束面向用户的对话和语音层。


- **目标**：做一个能实时语音对话、并能听懂指令后操作电脑的 AI 助手（全语音闭环）。
- **技术栈**：Python + sounddevice / openWakeWord / 声纹模型 / silero-vad / sherpa-onnx(SenseVoice) / DeepSeekHarness Python SDK（运行时主 Agent） / VoiceStudio 本地 TTS（主 Provider，支持 preset、提示词设定和音频克隆音色） / Edge TTS（可配置兜底） / asyncio。
- **架构原则**：前后端分离——决策/执行/安全核心与语音前端解耦，未来手机接入只需换前端（本次不实现）。
- **目录结构**：见 `design.md` 第十一节；其中 `models/`、`logs/`、`plans/` 和 `memory.md` 的实际内容按 `[本地运行数据]` 或 `[敏感信息]` 处理。


### 1.1 开源版本优先规则（硬规则）

从本项确认之日起，后续方案讨论、设计和实现默认以“可开源版本”为目标，不把当前用户的个人环境直接写死为通用实现。所有配置、文件和运行数据按以下类别标记：

| 标记 | 含义 | 开源处理方式 |
|---|---|---|
| `[通用规则]` | 所有用户都应遵守的安全、架构或交互规则 | 可以进入公开代码和文档 |
| `[用户配置]` | 每个使用者可以自行填写或调整的配置 | 放入配置模板、首次启动向导或环境变量说明 |
| `[本机配置示例]` | 当前用户的绝对路径、设备、解释器或本地目录 | 只能作为明确标注的示例；开源前替换为占位符或相对配置 |
| `[敏感信息]` | API key、token、密码、私钥、声纹和个人音频等 | 不提交、不写入示例、不出现在日志和截图中 |
| `[本地运行数据]` | 日志、记忆、执行计划、结果、缓存和个人历史 | 默认加入 `.gitignore`，仅提供空目录或示例模板 |
| `[示例值]` | 仅用于说明格式的假数据 | 必须明确不可直接使用 |

当前项目中的个人/本机特有内容必须特别处理：

- `[敏感信息]` `.env` 及其中的 DeepSeek API key、未来的 TTS/API 凭证：只保留 `.env.example`，由用户自行填写；真实密钥不进入仓库、日志、计划或截图。
- `[本机配置示例]` `<PROJECT_ROOT>`：当前项目目录；开源版本使用项目根目录或用户自行选择的安装目录，不把该绝对路径作为运行前提。
- `[本机配置示例]` `<STUDY_ROOT>`：当前用户的允许访问根目录；开源版本由用户在配置中填写 `allowed_root`。
- `[本机配置示例]` `<STUDY_ROOT>\AI工作区`：当前用户的默认工作目录；开源版本由用户填写 `default_work_dir`，并校验其位于 `allowed_root` 内。
- `[本机配置示例]` `<STUDY_ROOT>\\python`：当前用户的 Python 解释器/环境路径；开源版本不得假设该路径存在，应使用环境发现、虚拟环境或用户配置。
- `[本地运行数据]` `logs/`、`memory.md`、`plans/`、`execution_plan.md`、`plan.json`、`result.json`：可能含对话、路径、文件名、偏好和执行历史，默认不提交实际内容。
- `[敏感信息]` 个人录音、声纹样本、声纹 embedding、个人音色样本和个人训练模型：只提供模型目录说明和用户自行初始化流程，不提交个人数据。
- `[用户配置]` 唤醒词、助手称呼、人设、语音设备、阈值和热词：可以提供示例默认值，但必须支持用户替换。
- `[通用规则]` 系统目录黑名单、分级授权与 L3 第二重确认、路径越界拒绝、任意脚本禁用等安全规则可以公开，不能因开源而弱化。

开源前必须执行一次脱敏检查，至少检查：`.env`、API key、token、password、secret、credential、用户目录、绝对路径、主机名、用户名、录音、声纹、模型缓存、`logs/`、`memory.md`、`plans/` 和测试数据。未来应提供 `.env.example`、配置示例、`.gitignore` 和开源前检查清单；具体文件名和内容在后续“日志、隐私与历史记录”主题中定稿。

后续讨论中的默认表达规则：

```text
通用实现：使用配置项、环境变量、相对路径或用户输入
当前环境：只能写成 [本机配置示例]，不得作为通用前提
密钥和个人数据：写成 [敏感信息]，不展示真实值
日志、记忆、计划和缓存：写成 [本地运行数据]，默认不提交
```

### 1.2 运行时主 Agent 与接入方式（项目级决策）

本项目运行时确定采用 **DeepSeekHarness** 作为电脑语音助手的唯一默认主 Agent，负责闲聊、工作模式下的任务理解、信息分析、方案生成、错误解释和结果汇报。本文规则仅在使用本电脑语音助手时生效，不延伸为其他场景下使用电脑或其他软件的通用规则。

接入方式按以下优先级确定：

1. **正式运行时通道：DeepSeekHarness Python SDK**。电脑语音助手以 Python 主程序调用 SDK，管理会话、`session_id`、超时、事件和错误；使用受限 profile/插件。
2. **诊断、测试和故障恢复通道：命令行进程**。仅用于手动验证、诊断或用户明确要求的恢复操作，不作为正常运行时主通道。
3. **后续扩展通道：本地服务/API**。暂不作为 MVP 核心；待持续运行、多客户端或前后端分离需求明确后再设计。

启动与会话生命周期确定如下：

- 程序启动时只初始化 SDK 适配器并检查本地配置，不创建 DeepSeekHarness 会话，也不发起模型请求。
- 第一次收到实际闲聊或工作请求时，才延迟创建对应会话；没有用户请求时不得为了“预热”自行发送内容。
- 闲聊会话与工作会话完全分开。闲聊上下文只保留在当前进程内存中，连续闲置满 **30 分钟**后销毁，默认不落盘。
- 每项工作任务建立独立工作会话并绑定 `task_id`；任务完成、用户取消或任务失败后关闭该工作会话，不得把其计划、授权状态或工具结果直接沿用到下一项任务。
- 从闲聊切换到工作模式时，不自动传递完整闲聊历史；只传递用户本次明确提出的任务、用户明确引用的内容以及完成该任务确实必要的最小上下文。
- 每次 Agent 请求生成唯一 `request_id`。工作请求同时关联 `session_id` 和 `task_id`；形成计划后再关联 `plan_id` 与 `plan_version`，尚未形成计划时后两项为空，不得伪造占位计划。
- SDK 超时、崩溃、断线或返回格式错误时，立即停止当前流程，不自动重试、不自动改用 CLI、不自动切换 Claude Code/Codex；当前任务中已经存在的计划和授权全部失效。系统必须显示具体错误原因和可选解决方案，等待用户决定是否重新分析。

运行时职责分层：

```text
DeepSeekHarness = 理解、规划、解释、汇报
本地安全层 = SchemaValidator + ToolRegistry + PathGuard + PolicyEngine + ConfirmationManager
本地受控执行器 = 只执行冻结且获授权的 plan.json
ResultVerifier = 检查实际结果并生成结构化事实
```

硬边界：

- DeepSeekHarness 输出必须视为不可信输入，不能直接执行自然语言命令、脚本、路径或参数。
- 不向 DeepSeekHarness 开放默认 Shell、PowerShell、Python、批处理、任意脚本、管理员权限或任意鼠标键盘控制。
- 实际电脑修改只能由本地受控执行器按照通过校验、预检、用户授权和执行前重新校验的冻结计划完成。
- DeepSeekHarness 失败时不自动切换 Claude Code、Codex 或其他 Agent；必须停止当前任务、记录错误、使旧计划和授权失效，并等待用户决定是否重新分析。
- 用户明确选择其他 Agent 时，视为新的分析流程，必须重新扫描、重新制定计划、重新预检和重新授权。
- Agent 适配层保留可替换接口，但更换 Agent 不能改变本地安全层和项目级授权规则。

### 1.3 崩溃与重启恢复（项目级决策）

程序、Agent 崩溃或电脑重启后，不自动继续中断前的电脑任务；旧计划与旧授权全部失效。系统必须把审计记录作为线索，重新扫描电脑当前真实状态，将动作区分为已完成、未完成和状态不确定，向用户展示恢复报告。只有用户决定继续后，才创建新计划或新版本，并重新预检、重新授权。闲聊和实时语音可以恢复，但任务执行状态不得自动恢复。详细规则见 `shared/error-recovery.md`。

## 意图路由接缝（2026-09-24）

意图路由是现有电脑语音助手的统一业务边界，位置固定在 `ConversationManager` 与 Agent、只读工具、ActionPlan 和 Safety 之间：

```text
TextShell / ASR accepted final
→ ConversationManager
→ IntentRouter
→ RouteHandoff
→ AgentAdapter / 只读工具 / ActionPlan / Safety
→ authorization
→ Execution Ledger
→ Executor
→ Verification
→ Audit
```

- TextShell 与 ASR accepted final 共用同一条路由链；ASR 只负责提交已接受的 final 文本。
- `source=text_shell|asr` 用于追踪输入来源，现有 `Utterance.input_mode=text|voice` 继续保留，不互相替换。
- `IntentRouter` 是可替换分类 provider 的适配边界；Laya 不能绕过本地 `ConversationManager`、Policy/Safety 或执行器。
- 路由失败统一为 `ambiguous`，由会话层澄清或安全拒绝；Agent 不得在失败后自行重新判断。
- 路由分类不是授权，也不改变现有风险等级；所有副作用继续通过既有计划、预检、授权、账本、执行、验证和审计链。
- 设计契约唯一来源：`docs/superpowers/specs/2026-09-24-intent-routing-contract-design.md`。本次只同步设计文档，未修改 `app/`、`tests/`。
