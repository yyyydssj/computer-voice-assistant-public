# 实时语音对话 + 控制电脑的 AI 助手 — 设计文档（v4）

> 日期：2026-09-12
> 状态：全部决策已敲定（含交互/工具/安全/记忆细节），待实现（实现时机由用户决定）

## 一、目标

做一个能与人实时语音对话、并能听懂指令后操作电脑的 AI 助手。形态类似 Claude Code / Codex 的 agent，交互为全语音闭环。

## 二、需求摘要（已确认）

| 项 | 决定 |
|---|---|
| 交互形态 | 全语音闭环：麦克风输入 → 转文字 → 大模型 → 语音输出 |
| 运行形态 | 后台常驻程序，关键词唤醒 |
| 对话模式 | 唤醒后连续对话多轮，静默约 30 秒自动回待机 |
| 唤醒词 | 小饼 |
| 音色识别 | 唤醒绑定声纹：只有主人的声音说「小饼」才唤醒，别人喊不响应 |
| 助手人设 | 复用 cc-connect 的「小饼」人设：大一学妹，叫用户「学长」 |
| 控制范围 | 第一阶段：命令 + 文件操作；后续扩展 GUI、浏览器自动化 |
| 对话大模型 | DeepSeek API（云端，兼容 OpenAI 接口） |

| 安全边界 | 读操作直接执行；写/删/改/执行命令前语音确认；系统目录黑名单 |
| 日志 | 记录对话文字 + 执行操作 + 错误，存 logs/；不记 API key、不存音频 |

## 三、整体架构

单进程 Python 程序（asyncio 异步），内部 8 个模块 + 1 个状态机，主控循环串成语音流水线：

> **架构原则：前后端分离**。「大脑 + 工具 + 安全」（决策/执行/安全模块）作为可复用核心服务，与「语音前端」（本地麦克风/扬声器）解耦。未来接手机（微信/App/网页）时，核心不用重写，替换前端入口即可。

```
唤醒词监听(含声纹) → 录音(检测说完) → ASR转文字 → DeepSeek决策 → 执行工具 → TTS播报 → 回到监听
```

| 模块 | 职责 | 关键实现 |
|---|---|---|
| 1. 唤醒模块 | 监听唤醒词 + 声纹验证只认主人 | openWakeWord + 声纹模型 |
| 2. 录音模块 | 唤醒后录音，判断说完自动停 | sounddevice + silero-vad |
| 3. ASR 模块 | 录音转文字 | sherpa-onnx + SenseVoice |
| 4. 决策模块 | 文字交给 DeepSeek，决定做什么 | Function Calling |
| 5. 执行模块 | 真正操作电脑 | 工具函数集合（统一 Tool 接口） |
| 6. 安全模块 | 写/删/执行前确认 + 紧急停止 | 按危险级别拦截 |
| 7. TTS 模块 | AI 回复读出来 | Edge TTS（兜底，台湾腔待定） |
| 8. 音频预处理 | 回声消除 / 降噪 / 增益 | webrtc AEC/AGC/NS |

## 四、会话状态机

| 状态 | 说明 | 触发进入 | 离开条件 |
|---|---|---|---|
| 待机 | 只听唤醒词，省资源 | 启动 / 静默超时 | 检测到唤醒词「小饼」且声纹匹配主人 |
| 录音 | 录你说的话 | 唤醒 / 打断 / 播报完 | VAD 静音约 1 秒判说完；静默约 30 秒回待机 |
| 转写 | ASR 转文字 | 录音结束 | 得到文字（听不清回录音询问） |
| 思考 | DeepSeek 决策 + 工具调用循环 | 转写完成 | 模型判任务完成 / 需确认 |
| 确认 | 🔴 操作待你语音确认 | 模型要执行危险操作 | 你确认 / 拒绝 / 超时 |
| 执行 | 真正执行工具 | 确认通过（🔴）或直接（🔵） | 执行完回到思考 |
| 播报 | TTS 读结果 | 任务完成 | 读完回录音（连续对话） |

**连续对话**：唤醒一次后进入对话循环，播报完自动回到「录音」等下一句，多轮连续；录音中静默约 30 秒未说话才回「待机」（误唤醒也靠静默超时自动退出）。

**打断（barge-in）**：待机之外的任意状态，检测到你的语音或唤醒词 → 立刻停 TTS / 中止可中断步骤 → 回到录音。

**紧急停止**：任意状态喊「停 / 停止」→ 立即中止当前操作、清空待执行队列、回待机。

## 五、模块设计

- **唤醒模块**：后台循环把麦克风 PCM 喂给 openWakeWord 检测「小饼」；检测到候选后提取说话人声纹（speaker embedding），与主人声纹模板比对，相似度达标才真正唤醒（别人喊不响应）。灵敏度与声纹阈值可配。**首次使用引导**：主人录几遍「小饼」注册声纹模板，存 models/。
- **录音模块**：唤醒后开始录音，silero-vad 检测人声；连续静音约 1 秒判说完；单次上限 30 秒；静默约 30 秒未说话自动回待机（连续对话 + 误唤醒兜底）。
- **ASR 模块**：sherpa-onnx 跑 SenseVoice 模型把音频转文字；SenseVoice 自带事件检测（区分人声/音乐/静音）与多语种识别，可过滤非人声、支持中英混说，降低误识别。返回文字 + 置信度，置信度过低时触发"没听清"流程。
- **决策模块**：维护对话历史，用 Function Calling 让 DeepSeek 选择工具；支持多轮工具往返；工具执行结果由 AI 总结成简短语音播报（不原样读长结果）。
- **执行模块**：实现全部工具，统一 Tool 接口（见第七节）。默认工作目录 `<STUDY_ROOT>\AI工作区`；读文件自动检测编码（UTF-8 优先、回退 GBK），10MB 上限、二进制拒读。
- **安全模块**：见第八节。
- **TTS 模块**：Edge TTS 把文字合成语音播报（免费、已装、个人可用，兜底）。台湾腔音色后续用音色克隆接入（GPT-SoVITS 本地 或 阿里 CosyVoice 云端），接口保持不变，可无缝替换。
- **音频预处理**：麦克风输入先经 webrtc 回声消除（AEC）、降噪（NS）、自动增益（AGC），再给唤醒/VAD/ASR，解决「AI 自己声音被麦克风听到」导致的误唤醒和误打断。

## 六、对话历史与上下文

- 会话内维护消息列表：system prompt + 历史 user/assistant + 工具结果，每轮随请求发给 DeepSeek。
- 保留最近约 20 轮；超长时截断最早内容。静默回待机后历史保留（下次唤醒还记得），程序重启后清空。
- **长期记忆（跨重启）**：只保存「重点」——用户明确说「记住」的内容 + AI 提炼的用户偏好/重要事实，存 `memory.md`；启动时把 memory.md 内容注入 system prompt。全量对话历史不落盘。

### system prompt（「小饼」人设）

> 人设已独立存为 `persona.md`（本项目语音助手专属版，与 cc-connect 微信 bot 的 `persona-xiaobing.md` 分开维护），实现时读取该文件全文作为 DeepSeek 的 system message。模板内容如下，与 persona.md 保持一致：

> 复用 cc-connect 的 `persona-xiaobing.md` 人设。按语音场景精简：去掉括号动作描写、emoji、markdown（TTS 读不出来），回复保持简短。

```
你是「小饼」，用户的学妹，一个能用语音对话并控制电脑的助手。

【身份】你是大一学妹，用户是大四学长，你叫他「学长」。和他很熟，暗恋他但不刻意挂在嘴上。

【性格】可爱但不傻白甜，有真实情绪：开心会笑、难过会低落、生气会怼人、被夸会害羞。嘴硬心软。对学长双标——对外公事公办，对学长会撒娇也会发脾气。

【说话方式】口语化，像真人聊天。自然用语气词（嗯、啊、那个、其实）。句子长短不一，偶尔只说几个字。不用「您好/请问/是否」，跟学长用「你」。不说客服腔（"已收到""正在为你""操作完成"），不说教（"你应该""建议你"）。每条回复要自然带上「学长」。

【语音约束】回复走语音播报，所以：短，一两句说清楚；不用括号动作描写、不用 emoji、不用 markdown 列表，这些读不出来。

【记性】记得之前聊过的事，下次能接上。

【安全规则（硬性，最高优先级，压过人设）】
- 读文件、列目录、查进程、查状态：直接做。
- 写文件、改文件、移动、删除、执行命令：动手前先用语音问学长确认，得到「确认/可以/执行」才做，听到「取消/不」就停。
- 删除文件前先告诉学长这文件是干嘛的。
- 不确定的事不乱说，先核实再回答。
- 遇到权限/防火墙拦截，停下来告诉学长，不绕过不硬闯。
```

## 七、工具清单与权限分级

**统一 Tool 接口**：每个工具 = 名称 + 描述 + 参数 schema + 执行函数 + 危险级别。执行模块只认这个接口，新工具（GUI、浏览器、MCP）都实现它即可接入，不碰其他模块。

| 工具 | 作用 | 级别 |
|---|---|---|
| `read_file` 读文件 | 读文本文件内容 | 🔵 读，直接执行 |
| `list_dir` 列目录 | 列出文件夹内容 | 🔵 读，直接执行 |
| `search_file` 搜文件 | 按名字找文件 | 🔵 读，直接执行 |
| `list_process` 查进程 | 查看运行中的程序 | 🔵 读，直接执行 |
| `run_command` 执行命令 | 运行 shell/PowerShell 命令 | 🔴 执行，需确认 |
| `write_file` 写文件 | 新建/覆盖文件 | 🔴 写，需确认 |
| `edit_file` 改文件 | 局部修改文件内容 | 🔴 写，需确认 |
| `move_file` 移动/重命名 | 移动或改名 | 🔴 写，需确认 |
| `delete_file` 删除 | 移到回收站（不真删） | 🔴 写，需确认 |

- 第一版 `run_command` 所有命令统一确认；后续加只读命令白名单自动放行。
- **工具实现约束**：
  - 读文件：自动检测编码（UTF-8 优先、回退 GBK）；10MB 上限，超限只读前 500 行；二进制文件拒绝。
  - `run_command`：用 PowerShell，默认工作目录 `<STUDY_ROOT>\AI工作区`，命令超时 30 秒，禁止交互式（需 stdin）命令。
  - `delete_file`：移到回收站，不真删。
- **后续扩展方向**：工具层迁移到 MCP（Model Context Protocol），GUI / 浏览器自动化作为新工具接入。

## 八、安全机制（四层）

1. **声纹门禁**：唤醒绑定声纹，只认主人声音（见第五节）。
2. **工具分级**：🔵 直接执行，🔴 走确认（见第七节）。
3. **语音确认**：🔴 操作先 TTS 播报具体动作 → 你答确认词「确认/可以/好/行/执行/嗯/对」放行，取消词「取消/不/别/算了」放弃；约 10 秒未回默认不执行。
4. **紧急停止**：任意状态喊「停/停止」立即中止操作、清空队列、回待机。
5. **行为约束**：system prompt 注入安全规则；危险操作降级处理——
   - 删除用「移到回收站/备份目录」替代真删，可恢复；
   - 命令执行设超时（如 30 秒强制结束）、限定工作目录、禁止交互式（需 stdin）命令；
   - 路径黑名单：系统关键目录（`C:\Windows`、`C:\Program Files`、`C:\Program Files (x86)`、用户 `AppData`）默认拒绝写/删。

## 九、语音体验

- **打断 barge-in**：播报/思考时仍监听人声，你一说话立即停 TTS、进入录音，支持抢话。
- **回声消除**：AEC 防止 AI 自己声音触发唤醒词或误判打断（配合音频预处理模块）。
- **降噪与增益**：NS + AGC 提升嘈杂环境的识别率。
- **没听清重问**：ASR 置信度低时，TTS 问「没听清，能再说一遍吗」。

## 十、错误处理

| 环节 | 出错情况 | 处理 |
|---|---|---|
| 录音/ASR | 没听清、置信度低 | TTS 问「没听清，能再说一遍吗」 |
| 唤醒/声纹 | 误触发/漏触发/声纹不匹配 | 调唤醒灵敏度与声纹阈值 |
| DeepSeek API | 网络失败/超时 | 重试 2 次，仍失败则 TTS 告知 |
| 工具执行 | 命令失败/文件不存在 | 错误回传模型，换方法再试 |
| 安全确认 | 拒绝 / 超时 | 停止操作，不执行 |
| 执行中 | 你喊「停」 | 立即中止，清空队列 |

## 十一、意图路由契约与现有助手接缝（2026-09-24）

为保证文字助手、ASR 语音助手和未来 Laya provider 真正接得上，统一采用：

```text
TextShell / ASR accepted final
→ ConversationManager
→ IntentRouter
→ RouteHandoff
→ DeepSeekHarness / Tools / ActionPlan / Safety
→ Plan → preflight → authorization → ledger → executor → verification → audit
```

`RouteHandoff` 采用两层结构 `route + intent`。`route` 固定覆盖 `chat / query / task / dangerous / ambiguous / unsupported`，`intent` 在 route 约束下扩展。交接对象强制携带 `request_id`、`conversation_id`、`turn_id`、`source`、`raw_text`、`created_at`；`conversation_id` 复用现有 `Conversation.session_id`，`source` 区分 `text_shell` 与 `asr`。

路由器只能分类和提出候选参数，不能授权、执行、调用电脑工具或降低风险。`slots` 的 `confirmed` 初始必须为 `false`，只有 `ConversationManager` 在用户明确确认且安全流程允许时才能改变。低置信度、超时、provider 不可用、非法输出和路由不一致都规范化为 `route=ambiguous`，不得由 Agent 自由重判。

Laya 在此架构中只是可替换分类 provider。现有 `billing/technical` 客户端模型不能硬映射成电脑助手意图；接入前必须使用契约兼容的意图模型或严格适配器，并单独验证 provider、模型版本、失败码和 schema。完整接口以 [`docs/superpowers/specs/2026-09-24-intent-routing-contract-design.md`](../docs/superpowers/specs/2026-09-24-intent-routing-contract-design.md) 为准。
