## 1. 一句话结论

**AEC3 在本机真的有效（真机 ERLE 10.3 dB，最佳延迟提示下 15.5 dB），但单靠它压不干净**：
最佳情况下仍有 **80/289 ≈ 28%** 的 20 ms 帧残余回声超过打断能量门 600（未处理 59%）。
⇒ 阶段 0 的"条件性 no-go"修正为：**AEC3 不是不可用，而是不够用**；本机要安全打断需要
**AEC3 + 冷却窗口（已落地）+ 残余回声地板感知的动态门槛（未做）**。

## 3. 关键数据

| 项 | 值 |
|---|---|
| R4-B-3 回声/用户语音比 | **−7.1 dB**（回声 p50 846 / 用户 p50 1917）；ERL **13.7 dB**；回声自身 **+3.0 dB 超门** |
| R4-B-3 不可复现性 | 同日另一次用户语音 p50 只有 1037（差 **5.3 dB**）⇒ 比值在 **≈0 ~ −7 dB** 间浮动 |
| R4-B-4 双讲（首次） | 实测延迟 409 ms；ERLE **5.87 dB**；残差 519（p50 门下 1.3 dB）但 **137/289 帧超门**；双讲后用户语音 1648（**+8.8 dB vs 门**） |
| R4-B-4 复核（只放音 + 扫描） | 实测延迟 392 ms → ERLE **10.32 dB**；最佳 350 ms → **15.54 dB**、残差 132、**80/289 帧超门**；0–500 ms 内 ERLE **7–15.5 dB** |

## 4. 决策与下一步

1. **不接线**（本批只出证据）；接线前提是"残余回声地板感知的动态门槛"。
2. **三件套**（下批正题）：① `--aec-engine webrtc`（默认关）接线；② 已落地的 `--barge-in-cooldown-ms`；
   ③ 新增播放期动态门 `max(speech_threshold, 残余回声地板 × 裕量)`，地板由 AEC3 残差滑动分位数实时估计，
   并如实暴露 `residual_echo_floor_pcm16` / `gate_in_playback`。三件套完成后再真机试听（用户在场），
   启动时做一次 ~1 s 的**延迟探测**（延迟提示敏感：7–15.5 dB）。
3. 保留 `pyaec`/外接麦克风作为对照路线（未测）。

---

## 5. 局限（**不得伪造**）

样本量小（R4-B-3 一次、R4-B-4 两次）；用户语音电平两次差 5.3 dB ⇒ −7.1 dB 只是当次观测；
最佳延迟是**样本内拟合**；**系统音量未记录**；播放素材是离线 TTS wav 而非实时 VoiceStudio 输出；
延迟探测用我自己的互相关（与 AEC3 内部估计口径不同，差约 40 ms）；**未做**残余地板门槛、AEC3 接线、
三件套真机试听、耳机/外接麦场景；两个探针**未加单元测试**（开发工具，不在生产路径）。

## 6. 真机暴露并修掉的工具缺陷

`p10_r4b3_echo_ratio_probe.py` 首跑在打印含 `≫` 的档位标签时抛 `UnicodeEncodeError`（GBK 控制台，
与 P10 R4-A 同类）。已改为 `safe_write()`（不可表示字符按 `replace` 重试）并用合成报告离线验证；
**该次运行因此没有写出 JSON artifact**（数值取自控制台输出，命令可复现）。
