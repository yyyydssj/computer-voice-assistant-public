## 按证据重写

### 一、实现

- `app/tts/playback_worker.py`：持久化播放 worker 与 ticket 化 stop；ticket 状态 `STOP_ACKED` / `STOP_TIMEOUT` / `FAILED` / `UNKNOWN`；stop 超时、unknown 或后端失败后 fail-closed，禁止后续语音继续提交。
- `app/tts/real_playback.py`：区分 Windows waveOut 路径；播放子进程、worker、preview 生命周期一致。
- 仅凭 `STOP_ACKED` 不足以宣称扬声器静音或用户听见。

### 二、`STOP_ACKED` 的语义边界

- `not_submitted`：尚未提交设备，不以设备回执计时（`stop()`、`_start()` 中对未提交 ticket 的转移）。
- `waveOutReset` + `WAVEHDR` / `WOM_DONE` / `backend_buffer_returned`：backend 归还 buffer 的协议事实。
- 这不等于物理扬声器已经静音，也不等于用户已经听见；没有独立声学或人工证据时 `user_heard` 必须为 `None`。
- 后端（backend）事实、物理静音、用户听感三者必须分开登记，不得互相代替。

### 三、FIFO 与迟到事件

- worker 持久化并按 FIFO 串行处理播放 ticket；queued ticket 可取消且不触碰当前播放。
- 迟到 ACK 不得把已记录的 `STOP_TIMEOUT` 升级为 `STOP_ACKED`；stop 发生在 backend 阻塞期间时，worker 恢复后执行一次 best-effort backend stop（结果被忽略）。
- 真实 stop ACK 需要真实 Windows 设备与正式证据包；fake 后端或假 ACK 不能冒充真实设备故障证据。

### 四、真实证据缺口

- 真实后端事实：记录 `waveOutReset` 返回值、`WOM_DONE` / buffer 归还与 ticket 最终状态。
- 物理静音（`speaker_output_stopped`）：需要独立声学测量；当轮未取得可用信号——见 `artifacts/2026-09-28-P7-speaker-stop-acoustic/mic-array-controlled-measurement.json`，其 `status` 直接写明测量被阻塞，不得据此推断输出停止。
- 用户听感（`user_heard`）：需要用户明确确认；artifact `artifacts/2026-09-28-P7-stop-acked/2026-09-28-P7-waveout-stop-acked.json` 记录 backend `waveOutReset` + `backend_buffer_returned`，同时 `speaker_output_stopped=null`、`user_heard=null`。
- Edge 降级、真实 Provider、真机 stop ACK 未取得可复核证据。
