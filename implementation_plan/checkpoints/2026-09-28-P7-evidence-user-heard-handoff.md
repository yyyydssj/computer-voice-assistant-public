## 4. 建议的可执行人工确认方式

由后续验收对话将本地候选音频直接呈现给用户，让用户本人在其设备上选择播放；不要由助手替用户播放后代答，也不要用麦克风/程序状态代答。只有用户表示已播放后，再询问并记录：

1. 是否确实听到任何声音；
2. 如听到，是否听清固定文本 `P7真实链路基线。`；
3. 听感异常（无声、被截断、失真、音量过低、文本不清等）；
4. 关联的音频 SHA-256 和本次确认批次 ID。

建议向用户提供如下明确响应模板（用户可自由改写）：

```text
我已在本机播放批次 <批次ID>（音频 SHA-256 <摘要>）。
我本人：听到了 / 没有听到 / 无法判断。
若听到，固定文本听清情况：听清 / 未听清 / 不适用。
异常或备注：<可填写>
```

只有包含明确、第一人称、针对唯一批次的答复，才登记 `user_heard=true` 或 `false`；“已打开/已播放文件”但未回答听感、模糊回应、代他人回答或批次不明，一律维持 `None`。如当前界面不能嵌入播放音频，则请用户用本机播放器打开上述绝对路径并在当前对话按模板回答；不需要也不应要求录音、上传音频或开启麦克风。
