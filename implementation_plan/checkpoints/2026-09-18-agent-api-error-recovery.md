## 两条不可改变的最高原则

1. 项目是用户与 AI 的持续实时语音对话伙伴，既能自然闲聊，也能在对话中安全操控电脑；不能退化成单轮录音工具。
2. 所有面向用户的语言必须遵循用户确认的人物模板，保持自然、拟人和连续人格；人物表达不能削弱事实、安全或授权边界。

只有用户可以修改人物模板、提示词和 VoiceProfile。VoiceStudio 只负责语音数据面，不参与安全决策或电脑执行。

## 本轮已经定稿并写入文档

### 崩溃与重启

- 不自动续跑、补做、重试或回滚。
- 旧计划、旧确认和旧授权全部失效。
- 审计记录只是线索，电脑当前真实状态才是判断依据。
- 动作分类为 `completed`、`not_completed`、`state_uncertain`。
- 继续处理必须重新规划、预检和授权。

### 用户说“停”或点击停止

- 聊天/TTS：停止当前回复和播报，保持实时对话并继续监听。
- 等待授权：取消确认，关闭确认窗口，部分确认短语和旧授权失效。
- 执行任务：阻止后续动作；当前动作可安全取消则请求取消，不可安全中断则等待原子动作返回，绝不开始下一步。
- 停止后重新扫描；不自动回滚或补做；继续任务必须重新规划和授权。

### 取消、中止与关闭程序

- 用户取消：`user_cancelled`，只结束当前任务，不退出实时对话。
- 系统中止：`system_aborted`，用于风险、故障、前提变化、校验失败或状态不确定；不自动重试、跳过、修复或回滚。
- 正常关闭：按无任务、规划/等待授权、执行中三种状态安全退出。
- 执行中关闭先阻止后续动作并安全处理当前原子动作，扫描和记录状态后退出。
- 外部强制终止、关机或断电按崩溃处理，下次启动不得自动续跑。

### 已确认：Agent/API 故障策略已于 2026-09-18 定稿

用户已确认以下方案，正式规则已同步到 `../shared/error-recovery.md`、阶段 5/7 和计划导航：

1. **闲聊回复期间故障**：丢弃不完整回复，不写入正式历史，不自动重试或切换模型；保持助手运行和监听，用户明确要求后才使用新 `request_id` 重试。
2. **分析、规划或等待授权时故障**：任务标记 `system_aborted`；未完成或未通过 Schema 的模型输出不可作为执行计划；计划和授权失效；继续时重新分析、规划、预检和授权。
3. **本地执行期间 Agent 故障**：冻结计划执行原则上不依赖 Agent 持续在线；若故障影响任务控制，则阻止后续动作、安全处理当前原子动作、重新扫描，任务中止且旧授权失效。
4. **执行已完成，仅自然语言汇报失败**：不得把真实执行结果改成失败；保留 `ResultVerifier`、`result.json` 和审计事实，界面用本地正式模板展示结果，只单独记录“Agent 汇报生成失败”，不得重复执行。
5. **统一禁止**：不自动重试，不自动遵循 `Retry-After` 重试，不自动切换 CLI、Claude Code、Codex 或其他模型；不使用不完整流式文本生成计划、调用工具或请求授权；敏感错误详情只在本地界面脱敏显示。

上述 Agent/API 故障策略已经确认，不要再次询问。

## ASR 故障与恢复子项已定稿

### ASR 整体不可用

- 自动进入文字输入模式，不自动切换未经配置的识别服务。
- 键盘输入仍调用同一个 DeepSeekHarness Agent；电脑任务仍经过完整本地安全链。
- L2/L3 授权不降级；TTS 可用时可以“文字输入、语音输出”。

### ASR 恢复后

- 后台只做低频本地健康检查，不拿用户正在说的话测试，也不上传测试音频。
- 连续多次检查通过后只提示恢复，不自动切回语音输入。
- 只有用户明确请求后，才在安全空闲点切回；不得打断键入、回复、方案、授权、执行或恢复扫描。
- 切回前清理旧输入状态、创建新会话边界并完成本地麦克风与 ASR 联合测试；失败则保持文字模式。

上述两项已经确认，不要再次询问。

## TTS 主 Provider 故障衔接已定稿

- VoiceStudio 故障只影响语音输出，完整文字和电脑任务继续，安全与授权状态不变。
- 按完整句切换：当前句未播放时可由用户预先指定的 Edge 音色接替；已播放半句时停止本轮，不混声、不重播，从下一轮开始使用 Edge。
- 未配置 Edge 时进入文字输出；Edge 也失败时转纯文字，不尝试第三个 Provider，不循环重试。
- L2/L3 授权始终以正式界面为准，TTS 不能代替、阻塞或批准授权。
- VoiceStudio 恢复后只从下一轮新回复恢复原 VoiceProfile，不重播旧内容，也不覆盖用户配置。
- GitHub 源码对比已记录在 `../research/tts-fallback-github-comparison.md`；主要借鉴 LiveKit 的“已输出音频后不再对当前片段 fallback”和可用性事件，以及 Pipecat 的显式可用状态与应用层恢复策略。

上述 TTS 故障衔接已经确认，不要再次询问。

## 启动阶段 ASR/TTS 模型加载失败与超时已定稿

- ASR/TTS 不得阻塞正式界面、文字输入、Harness、本地安全链和审计基础设施启动。
- ASR 与 TTS 分别设置有上限的启动检查/加载期限；失败或超时后清理临时资源并标记 `unavailable_startup`，不无限等待、不循环重启。
- ASR 启动失败立即进入文字输入；TTS 启动失败保留文字输出，只有预先配置的 Edge 音色才可为后续新回复兜底；两者都失败时使用纯文字。
- 启动降级不改变电脑任务、计划、授权和安全链；组件随后恢复也不得自动打断当前文字输入或抢回当前回复。
- 上次遗留电脑任务不在启动阶段自动续跑，按崩溃/重启规则重新扫描和授权。

上述启动阶段模型故障策略已经确认，不要再次询问。会话级预热、运行期故障、Provider 冷却、恢复探测和重新启用规则也已于 2026-09-19 整体确认，见下节。

## I.9 音频组件会话级故障与恢复已定稿

- ASR/TTS 会话预热独立、可取消、有上限，不阻塞文字输入或文字回复；预热材料不得进入正式 Agent、停止或授权流程。
- ASR 运行期故障只关闭当前 utterance；顺序不确定或不完整的结果不提交，已创建请求后不得重发。
- TTS 以实际句子播放事实为边界；半句失败不换声、不重播，旧回复剩余内容不跨 Provider 续播。
- 音频故障不改变任务、计划、授权、执行、验证或审计；正式界面始终是 L2/L3 授权事实来源。
- Provider 先冷却再用固定无隐私材料探测；ASR 恢复后等待用户明确切回，TTS 恢复后只从下一轮新回复生效。
- 恢复创建全新的 session、utterance、请求和队列边界；旧音频、旧请求和旧授权不得复用。

上述规则已经整体确认，不要再次询问。具体实现参数留待真机测试，但必须有上限。
