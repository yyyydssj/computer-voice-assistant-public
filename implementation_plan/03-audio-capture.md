## 已确认设计

### 设备选择与生命周期

- 默认使用用户明确选择的固定输入设备和固定输出设备，不自动切换到任意其他设备。
- 设备使用稳定的设备标识保存，不把个人设备名称、路径或硬件信息写死到开源方案。
- 也可由用户显式选择 `system_default` 模式；Windows 默认设备变化时显示通知，并在当前语音轮次结束后尝试切换。
- 新设备不在当前录音或当前播放句子中途切换，只从下一轮对话启用。

设备状态至少包括：

```text
checking / ready / unavailable / busy / disconnected /
permission_denied / incompatible / switching
```

### 异常处理

- 启动或进入语音模式时先枚举和检查配置设备；检查失败时不启动语音监听，保留文字模式并显示具体原因。
- 麦克风被其他程序占用时，不静默改用其他设备；提示用户关闭占用程序、选择设备或手动重新检查。
- 麦克风运行中断开时，停止当前录音，取消当前 ASR 输入，删除临时音频，并将当前语句标记为 `input_interrupted`；不把不完整内容发送给 Agent。
- 输出设备断开时停止播放、清空未播放 TTS 队列，不自动重播旧回复；文字回复继续保留在界面。
- 设备异常不会改变 Agent、计划、工具权限或安全策略；未完成的语音确认立即失效，不能产生授权。
- 用户手动选择新设备后，才允许从下一轮对话启用；设备恢复不触发无限重试。

## 临时音频与诊断模式

- 音频链路默认在内存中处理 `AudioFrame`、pre-roll、VAD、AEC、降噪和 ASR 输入，不为每轮实时对话生成录音文件。
- 仅当 ASR Provider 必须接收文件路径时，才在本程序专用的本地临时目录创建随机命名文件；完成、失败、取消、打断、没听清或设备异常后立即清理。
- 异常遗留文件由看门狗在最长 60 秒内清理；程序重启时只处理能验证为本程序创建的遗留文件，不扫描或删除其他程序文件。
- 删除失败时停止复用文件并有限重试；最终失败则按人物模板简短提醒，界面展示具体路径、原因和手动清理方法。
- 用户主动诊断模式与正常实时对话隔离：默认关闭，只能由用户开启；开启前展示保存范围、位置和期限，关闭后立即恢复默认不保存。

## 原方案补充：音频实现预留

### 7.8 音频实现预留

MVP-1 先按键触发，但音频层从一开始按流式帧设计：

```text
AudioFrame
→ 输入队列
→ pre-roll 环形缓冲
→ VAD
→ 录音缓冲
→ ASR
```

预留采样率、帧长、设备、pre-roll、VAD 开始/结束阈值、最短人声、静音时长和最长录音配置。后续增加唤醒、打断和 AEC 时，不重写录音层。
